# Connectivity / Channels / MCP Troubleshooting

Use this page when configuration appears to exist, but messages do not arrive or tools are unavailable:

- Hub / SSE connectivity failures
- Telegram channel does not receive or reply
- CommHub MCP tools are not injected, so the agent cannot actively call `send_task`

Start with the smallest diagnostic path, then branch by symptom.

## 1. Run doctor first

```bash
anet doctor
```

Focus on these checks:

| Check | Healthy output | What to do when it fails |
|---|---|---|
| Global config | Shows the current hub | If missing, run `anet login --hub http://127.0.0.1:9200 ...` |
| CommHub reachable | `/health` responds | Confirm `anet hub start` is running |
| Nodes configured | Lists `.anet/nodes/` in the current directory | Change into the project where the node was created |
| `.mcp.json commhub channel` | configured | Recreate the node or follow the CLI repair hint |
| Telegram channel env | Token file exists and is non-empty | Reconfigure the channel if the token was lost |

For repairable local configuration issues:

```bash
anet doctor --fix
```

`--fix` repairs legacy config fields, expired or wrong-type node tokens, and preserves session / channels / role whenever possible.

## 2. Inspect channel status

```bash
anet channel status <node>
```

Check:

- the real `access.json` path under the current node directory
- whether the allowlist contains the Telegram numeric user id
- whether there is pending pairing state
- whether a bot token is configured

To list bound channels only:

```bash
anet channel ls <node>
```

## 3. Telegram does not receive messages

Check in order:

1. Is the bot enabled in BotFather?
2. Does `anet channel status <node>` show your numeric user id in the allowlist?
3. Did you restart the node after editing channel config? Channel config is read at process start.
4. Does node startup log a channel failure warning? Recent `anet node start` / `anet node resume` emits explicit warnings for failed channels.

Common recovery:

```bash
anet node stop <node>
anet node start <node>
```

## 4. Agent cannot actively delegate

If the agent says it has no `send_task` / `get_all_status` tool, check the runtime:

| Runtime | Expected behavior |
|---|---|
| `claude-agent-sdk` | agent-node wrapper injects CommHub tools |
| `codex-sdk` | each node gets CommHub tools; Codex nodes can actively call `send_task` |
| `grok-build-acp` | core delegation is guarded by the agent-node wrapper; native Grok backend-tool expansion remains preview |
| `claude-code-cli` | CommHub MCP comes through project `.mcp.json` / node-server |

Diagnostic path:

```bash
anet doctor
anet node stop <node>
anet node start <node>
```

Then ask the node for a minimal tool call:

```text
Please call get_all_status and tell me which agents are online.
```

If tools are still missing, check whether `.mcp.json` was generated by an old version. Do not copy `.anet/node-server.js` from another project.

## 5. Message sent, but nobody received it

From the user's point of view, common cases are:

- Target alias is wrong or deleted: recent versions should return a structured error.
- Target is offline: the message may enter the inbox, but the sender should be told that the target is offline and the message was queued.
- Target is online but busy: check the Dashboard / Tasks page for pending / working state.
- Hub is restarting: SSE should reconnect automatically; if it does not recover, run `anet doctor`.

## 6. When to recreate config

Use this order:

1. `anet doctor`
2. `anet doctor --fix`
3. restart the node
4. only then consider regenerating `.anet/node-server.js` or recreating the node

Do not delete the whole `.anet/` directory casually; it contains node identity, sessions, and channel configuration.
