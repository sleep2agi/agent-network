# 定时任务

桌面应用和 Android 的「定时任务」页。到点后，Hub 给指定节点派一条会话任务。它不是[任务](/guide/tasks)页上的卡片，也不是命令行的 [Goal 与 Loop](/guide/goals-and-loops)。派出去的那条任务用[任务生命周期](/concepts/task-lifecycle)里的状态。

iOS 仍走 TestFlight，公开链接还没开。本页按桌面和 Android 上能点到的界面来写。新建、筛选和详情上的字目前仍是中文。冲突对比，以及下面说的连续跳过那一行，会跟着应用语言变。

## Hub 计划和节点计划

页上有两个标签。

**Hub 计划**是在这里建的。点「新建定时任务」，Hub 按你设的时间把任务内容派给一个节点。节点页的「定时任务」也能打开同一张表，并预先选中那个节点。

**节点计划**不是用这张表建的。节点把自己机器上的计划上报上来，种类有 crontab、systemd、tmux、playwright 和自定义。还没有上报时，页面写「节点升级后会自动上报本机 crontab 等计划。」

下面的频率、时区、错过和跳过，都只说 Hub 计划。

## 怎么建

- **名称**。最多 120 个字。
- **执行节点**。必须是当前网络里已经有的节点，例如 `demo-node`。
- **任务内容**。到点发给节点的正文。最多 10000 个字。
- **优先级**。高、普通、低。不选就是普通。
- **类型**。只有四种，没有 cron 表达式。
- **错过执行**。见下。
- **时区**。IANA 名字，例如 `Asia/Shanghai`。打开表单时填的是这台设备的时区。通过接口创建时如果没带时区，Hub 用 UTC。写错的时区会被拒绝。每天和每周的钟点按这个时区解释，夏令时也走这个时区的规则。列表里只有时区和设备不一样时才把时区附在频率后面，避免把「每天 09:00」看成设备本地的 9 点。详情里始终看得到时区。

类型：

- **单次**。一个还没到的时刻。跑完之后变成「已完成」，不能再改回「进行中」。
- **间隔**。最短 1 分钟，最长 365 天。
- **每天**。`HH:mm`。
- **每周**。`HH:mm`，至少选一天。

错过：晚了不超过 1 分钟仍算这一次，照常执行。超过 1 分钟才算错过。

- **补跑一次**。不选时就是这个。Hub 停过，或这次已经晚了超过 1 分钟，恢复后最多补跑一次，不会把错过的每一次都补回来，然后排到下一个还没到的时刻。更早的 Hub 如果没带这个字段，也按补跑一次。
- **跳过本次**。错过的那次不跑，执行记录里留一行，直接等下一次。

「进行中」可以「暂停」。暂停后没有下次时间，详情写「已暂停，恢复后继续」。点「恢复」再算下一次。「取消计划」之后不会再执行；再点一次也还是已取消。已完成和已取消不能改回进行中。

改名称、任务内容或优先级，不会把下次时间重算一遍。改了频率或时区、从暂停恢复、或者这条进行中的计划没有下次时间，才会重算。

进行中和已暂停还可以「立即执行」。它也遵守下一节的跳过规则，而且不会改掉原来的下次时间。

桌面是居中对话框，手机是整页。够宽时左边列表、右边详情。列表按进行中、已暂停、已完成、已取消筛选。

## 上一次还没结束就跳过

新建的 Hub 计划都是：上一次没结束，这一次就跳过。

到点时，如果这个计划上一次派出的任务还停在 `created`（已创建）、`delivered`（已送达）、`acked`（已确认）或 `running`（执行中），这一次不派新任务。执行记录记「已跳过」，原因是「上一次还没结束」。这次跳过没有等待上限，不会过一会儿改成照样派发。计划自己的下次时间照样往前走。

节点离线时，这一次记成「排队中 · 节点离线」，不推送。它仍算没结束，所以后面的点会继续跳过，直到这次任务结束。

**桌面 0.2.150 起**，执行记录里连续两条及以上、原因都是「上一次还没结束」的跳过，合成一行：「已跳过 N 次（HH:MM–HH:MM）」，并写在等哪一次。单独一条跳过，或者别的原因（节点不存在、节点不可用、错过被跳过），仍各占一行。Hub 仍是每个点存一行，合成只发生在客户端这一页。被等的那次不在这一页记录里时，行内会说明，不会猜。更早的桌面版逐条列出，不合行。

## 编辑时刚好执行了一次

**桌面 0.2.150 起**，正在编辑时这条计划执行了一次，保存不会把表单里的内容丢掉。客户端比较你改过的项和服务器上改过的项。两边改的不是同一项，就留着你的草稿再保存。只有同一项被改成了不同的值，才显示对比：「你的修改」和「最新版本」。可以「用我的覆盖」（按你的改动保存）、「用最新的」（冲突项改成服务器上的，先留在表单里）或「继续编辑」（草稿不动，对着新的一版接着改）。计划已被取消或删除时，改动仍留在表单里，但不能保存。更早的桌面版在这种保存冲突时可能把整份草稿丢掉。

## 已知问题

Hub 0.9.0-preview.67 起修复。Claude Code 节点在这版发布并升级之前，可能收不到定时任务推送。执行记录会像节点离线那样记成排队，节点却没有收到，后面的执行又因为「上一次还没结束」被跳过。

agent-network 2.3.0-preview.118 起，Claude Code 节点收到回复也会被唤醒。节点要更新到这版并重启后才生效。
