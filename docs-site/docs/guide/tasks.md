# 任务

桌面应用和 Android 的「任务」页，用来排人自己的工作。它和 [Web Dashboard](/guide/dashboard) 里的收件箱不是同一页：收件箱看的是会话里派来的消息；这一页是任务卡片。Agent 通过 [需求池接口](/api/mcp-tools#需求池-任务看板) 读写的是同一批记录。字段、权限和同步方式以那一节为准，这里不重复。

也不要和[派给 Agent 的会话任务](/concepts/task-lifecycle)搞混。那一页讲的是消息任务的状态机，不是这里的卡片。

iOS 仍走 TestFlight，公开链接还没开。本页按桌面和 Android 上能点到的界面来写。

## 列表和看板

导航里的「任务」。手机在底部，展开的宽屏在左侧。

顶栏可以在「列表」和「看板」之间切换，也可以筛选、新建。看板三列是「需求池」「进行中」「完成」（英文界面是 Backlog / In progress / Done）。桌面把卡片拖到另一列；手机长按卡片打开菜单。点开卡片，在右侧详情里改。

左侧可以按「全部」「我负责的」「未分配」「按 Agent」「按节点」或项目筛选，也可以看「派发记录」。

更早的 Hub 上，描述、子任务、子需求或 Issue 绑定还不可用时，客户端会提示升级。桌面自带的本地 Hub 已经支持本页说的这些操作。

## 项目

左栏「管理项目」里新建。项目有颜色，任务卡片上会带这个标签。可以按项目筛选。

项目名最多 40 个字，不能和已有的重名。归档之后不能再选；已经挂在上面的任务仍保留这个项目。

## 子任务和子需求

这是两样东西，界面用的词不一样：

- **子任务**（英文界面是 Checklist）：挂在一张卡片上的勾选清单。可以增删，桌面可以拖动排序。卡片上显示完成进度。
- **子需求**（英文界面是 Subtasks）：另一张任务卡片，挂在当前任务下面。详情里「＋ 新建子需求」。最多 5 层。卡片显示子需求进度，也能跳回父需求。筛选里可以「只看顶层」。删掉父任务后，子需求还在，并变成顶层。

## 预计完成

可以是一整天，也可以精确到秒。时刻在界面上按你的本地时区显示；Hub 存的是 UTC。全天的任务在本地那天结束前不算逾期。详情里看得到到秒的本地时刻；有指针时，悬停也能看到。

### 到期提醒

Hub 每 10 分钟查一次没完成、没归档、设了预计完成的任务，提醒负责人和参与人（人）。打开节点提醒后，负责 Agent 也会收到一条不需要回复的消息：

- **即将到期**：全天任务明天到期，或时刻在 24 小时内。每个预计完成时间提醒一次。
- **今天到期**：今天到期且还没到。每个预计完成时间提醒一次。
- **已逾期 N 天**：每天最多一次；逾期超过 7 天不再提醒。

「今天」按东八区（Asia/Shanghai）算。任务完成、归档、清空或推迟预计完成，提醒马上停；推迟之后按新时间重新提醒。Hub 重启不会重发。

提醒出现在与负责 Agent 的会话里；没有负责 Agent，或你看不到它时，发信人是「任务提醒」。

开通时不补发：每个网络第一次被检查的那一刻记为起点，只有在这之后才逾期的任务会收到「已逾期」提醒。打开这个功能，或把网络加进白名单，都不会把以前的逾期任务一次性提醒一遍。

运维可以用环境变量调整：

- `COMMHUB_DUE_REMINDERS=0`：关闭（除非同时设了下面的 `COMMHUB_DUE_REMINDERS_NETWORKS` 或 `COMMHUB_DUE_REMINDERS_OWNERS`）。
- `COMMHUB_DUE_REMINDERS_NETWORKS=<网络 id,网络 id>`：只提醒这些网络。和 `COMMHUB_DUE_REMINDERS=0` 一起用时，只给这些网络打开，别的网络照样关着——一个 Hub 上有多个团队、只想先给自己的网络开时用它。
- `COMMHUB_DUE_REMINDERS_EXCLUDE_NETWORKS=<网络 id,网络 id>`：功能开着时，这些网络不提醒；白名单里点了名也一样排除。
- `COMMHUB_DUE_REMINDERS_OWNERS=<用户 id,用户 id>`：只提醒负责人在名单里的任务。这些任务照常提醒负责人、参与人和负责 Agent；别人负责的任务（包括没有负责人的任务）一条都不发。和网络名单同时设时两个条件都要满足。和 `COMMHUB_DUE_REMINDERS_NETWORKS` 一样，在 `COMMHUB_DUE_REMINDERS=0` 时也能单独打开——几个团队共用同一个网络、网络名单分不开时用它。启动日志会多出 `; only cards owned by <用户 id>`。开通不补发按「网络 × 负责人」各算起点：把一个人加进名单，从加进来那一刻算起。
- `COMMHUB_DUE_REMINDER_NETWORKS=<网络 id,网络 id>`：旧名，只提醒这些网络，不设就是所有网络；它不能在 `COMMHUB_DUE_REMINDERS=0` 时打开提醒。

上面几个名单：值为空或只有空白、逗号，等于没设。名单一旦设了就只发名单里的网络（`COMMHUB_DUE_REMINDERS=1` 也一样）。都不设时行为不变。Hub 启动时在日志里打一行生效范围（只有网络 id），例如 `[due-reminders] scope: only networks <网络 id>`。范围外网络的任务不会被读出来，也不会记起点；以后把它加进来时，从加进来那一刻算起。
- `COMMHUB_DUE_REMINDER_NODES=1`：也给负责 Agent 发消息。默认不发，只提醒人。
- `COMMHUB_DUE_REMINDER_TICK_MS`：检查间隔。
- `COMMHUB_DUE_REMINDER_TZ`：时区。
- `COMMHUB_DUE_OVERDUE_MAX_DAYS`：逾期提醒的天数上限。

Agent 用 `requirements_list` 查到期任务：`overdue: true` 只列逾期的，`due_within_days: N` 列今天到 N 天后到期、还没逾期的（0 = 今天）。两者都只看没完成的任务。REST 列表用同名参数（`overdue=1`、`due_within_days=N`）。


## 投递与告警的阈值

任务「投出去之后」的行为由三个阈值控制。它们都只影响**告警与收尾**，不影响任务本身的投递重试语义。

### 目标离线：30 分钟收尾

任务投给一个**已离线**的节点，不会一直挂着等 24 小时：超过 30 分钟就置为 `expired`，ack 掉它的 inbox 行，并给发送方一条通知。写入的事件是 `task.expired`。

只处理「目标明确不在」这一种：

| 目标状态 | 处置 |
|---|---|
| `offline` / 没有 session 行 | 超过阈值 ⇒ 过期 |
| `working`（正在跑别的任务） | **不处置**，走 `queued_behind_busy` 告警 |
| 节点已取走（`consumed_at` 有值） | 不处置（交给 orphan 判据） |

- `COMMHUB_OFFLINE_DELIVERY_TTL_MINUTES`：默认 `30`，设 `0` 关闭。

### 投递卡住的告警：按目标自己的节奏判断

「任务投出去了、目标还没开始消费」会写一条告警事件，但阈值不是全局常数，而是：

```
等待时间 > max(全局下限, 该目标自己的 p99 × 1.5)   （上限 30 分钟）
```

- 全局下限：10 分钟（第一档）、30 分钟（第二档）；
- 「自己的 p99」由 Hub 每小时从最近 7 天的成功任务里算一次（样本至少 20 条，否则退回全局）；
- 上限 30 分钟：再慢的节点，等满 30 分钟也必须响。

这样「全员都在跑长任务」时不会一屏告警，而「某一个节点单独卡住」仍然会显形。目标正在跑别的任务时，事件是 `queued_behind_busy_*`；目标空闲或离线时才是 `delivered_stale_*`。

排障时可以看每一档阈值实际生效多少（表是缓存，清空即退回全局）：

```bash
sqlite3 ~/.commhub/commhub.db "SELECT alias, p99_seconds, samples FROM alias_latency_baseline ORDER BY p99_seconds DESC LIMIT 10;"
```

### 定时任务连续失败：自动放慢

一个排程连续失败时不会一直按原间隔重试：

```
连续失败 < N  → 不变
连续失败 ≥ N  → 间隔 × 2（每多失败一次再翻倍，上限 1 小时）
成功一次      → 立刻恢复原间隔
```

- `COMMHUB_SCHEDULE_FAILURE_BACKOFF_RUNS`：默认 `6`，设 `0` 关闭；
- 只对 `interval` 类型且状态为 active 的排程生效；
- 与「无变化退避」（`no_change_backoff`）互斥——两者不会同时改写同一列。

> 为什么要它：上游额度打满这类外部原因，若每 3 分钟重试一次，24 小时能制造几百条失败记录，把真正的故障率淹没。放慢重试既保留了自愈能力，又不会污染指标。

## GitHub Issue

详情里「＋ 绑定 Issue」。粘贴 Issue 链接，或写成 `owner/repo#123`（编号 1–10000000）。可以绑多个，最多手动绑 8 个，绑定和解绑马上保存。卡片和列表上显示关联数量，点一下在浏览器打开。

从 GitHub 同步进来的那条来源标着「同步来源」，不能在这里解绑。同一个 Issue 不能绑两次。

给 Agent 做幂等同步时用 `external_ref`（形如 `github:owner/repo#123`），见 [需求池 / 任务看板](/api/mcp-tools#需求池-任务看板)。
