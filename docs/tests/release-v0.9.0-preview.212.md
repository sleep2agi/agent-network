# 0.9.0-preview.212

> 两类「什么都没干却在烧」的浪费各改一处：**连环轮询**与**同一秒全员唤醒**。

`get_task` 在「连着打」时会自己带上节奏提示 —— 不用等任何客户端升级。

## 背景（实测）

一个节点在空闲等待里以约 13 次/分钟连续拉了 8 小时 `get_task`：

```
每小时 get_task：256 / 565 / 647 / 703 / 770 / 855 / 893 / 972 / 736
⇒ 约 6000 次，每次都是一整轮 LLM 调用
```

这 6000 次没有推进任何工作，只是在问「好没好」。而子任务的最终结果本来就会通过
`parent_task_id` 自动 chain 回上游。

⚠ 不是所有高频轮询都是这个形状。按「逐小时计数是否恒定」可以分成两类：

```
恒定（±5%）   ⇒ 客户端定时器，不读响应内容 ⇒ 本版的 pacing 对它们无效
有起伏        ⇒ LLM 一轮一轮打           ⇒ pacing 有效
```

所以本版**只对后者有效**；定时器那一类只能改客户端（已在推）。

## 改法

`get_task` 的响应在超过阈值（60 秒内第 5 次起）时多一个字段：

```json
{
  "ok": true,
  "task": { "...": "..." },
  "pacing": {
    "calls_last_60s": 7,
    "recommended_interval_seconds": 60,
    "note": "每次 get_task 都是一整轮 LLM 调用。子任务的最终结果会通过 parent_task_id 自动 chain 回上游，所以不必连续轮询 —— 建议隔 60 秒以上再看。"
  }
}
```

- **不返回错误、不改状态**：忽略它也照常工作，信息不缺、行为不破
- 计数按 (调用方, `task_id`) 分开：同时等多个子任务不会被误判成连环打
- 偶发查询（隔几分钟看一眼）永远碰不到这句话

## 为什么放在 Hub 侧

`get_task` 是 Hub 提供的 MCP 工具。放在这里，**发版即对所有节点生效**；
放在 agent-node 的提示词里，则要发配对版本、且只有升级过的节点才会变。

## 测试

```
server/src/poll-pacing.test.ts：7 pass / 0 fail
  · 偶发查询不提示
  · 60 秒内超阈值才提示（带次数与建议间隔）
  · 隔 60 秒以上再看 → 计数清零、不再提示
  · 不同 task_id 互不累加
  · 文案必须含「60 秒 / chain 回上游 / 一整轮 LLM」
  · key 数量有上限（含「所有 key 都在窗口内」时的硬砍）
agent-acl-http + task-late-reply-http：64 pass / 0 fail（加字段未打破既有断言）
```

## ⚠ 期望管理：它只对**一半**的高频轮询有效

同一份账本按「逐小时计数是否恒定」再分一层：

```
TMA空间测试  get_task   448 448 448 448  ← 恒定（每 8.0 秒一次）＝ 客户端定时器
TMW测试欧    org_whoami 233 228 227 228   ← 恒定（每 15.8 秒一次）＝ 客户端定时器
TMW微软欧    get_task   770 855 893 972   ← 起伏 ＝ LLM 一轮一轮打
```

**定时器看不见 `pacing` 字段**（它不读响应内容），所以这一版对那类节点无效 ——
那类只能靠客户端改（已派 通信客户端欧，卡 `#3043`）。

## 同一版还带了：广播的通知进批内（`#2721` 下半句）

上个月的分批改造只摊开了**入库**，通知（SSE 推送）仍留在所有批次之后：

```
before:  入库(3 批) → 让出×3 → notify×384（同一个 tick）
after :  入库(50) → notify(50) → 让出 → 入库(50) → notify(50) → 让出 → …
```

而 2026-10-27 那次 **143.9 秒 timer 饥饿**的成因正是「同一秒 384 个 agent 同时醒来」——
入库摊开对客户端几乎无感，唤醒摊开才是解法。

同时把 notify 逐条 try/catch：挪进批内后一次推送失败会让**剩下的人收不到广播**，
而原来「入库已全」时不会 —— 广播不能因为 SSE 断了就漏发。

判据（等下一次 ≥300 收件者的大广播）：`event_loop.max_gap_ms` < 20s、RSS < 广播前 2 倍。
无广播时的基线是 1.17 秒 / 0 stall。
