参照机群 35 台节点散在 **27 个 workspace**(25 个只装 1 台)。三条真实共享链共 8 台,兄弟扫描只看得见 **2 台**;三台 `auth.json` **整文件字节全等**的那组分属三个 workspace,**整组漏掉**。判据没错,**取集错** —— 而它的失败形态是**沉默**,与「确实没有冲突」逐字同形。

## 本版怎么做的

- 节点除了写自己目录里那份,再往 `~/.anet/codex-auth-fingerprints/`(目录 0700、文件 0600)发布一份,文件名 = **规范化节点目录路径的哈希**;读方枚举该索引,两个来源按规范化节点目录去重。兄弟扫描保留,节点目录里那份也保留 —— 它是节点「公布自己」,也是索引写失败时的兜底。
- **不用 alias 当文件名**(跨 workspace 不唯一,重名互相覆盖 = 重造盲区);**也不用 `node_id`**(旧配置上可能为空需要兜底,于是同一个节点在两条启动路径下会写出两个文件名,变成假阳性)。`node_id` 记在记录内容里。
- 🔴 **陈旧判据用「存在」不用「年龄」**:记录里存 `node_dir`,读时 `stat`,目录没了就跳过并**删掉索引项**;年龄从不过滤,只在超过 7 天时附注。理由是现场数据 —— 最严重那组三台里**两台没在跑**、29 份凭据里 **6 份数天未动**,而它们**仍然持有**共享凭据;按年龄截断恰好会藏掉最该报的冲突。假告警比沉默更坏,因为它训练人忽略这个告警。

## Install

```bash
npm i -g @sleep2agi/agent-network@2.3.0-preview.99
```

## Upgrade

```bash
npm i -g @sleep2agi/agent-network@2.3.0-preview.99 @sleep2agi/agent-node@2.5.0-preview.75
```

🔴 **两个包要一起升。** 不经 CLI 起的节点靠 `agent-node` 里那份;经 CLI 起的靠本包这份。只升一个,另一条路径上的节点仍是旧行为。

## 边界与证据

- 行为本身不变:仍然**只告警不拒启**、仍然**只读别的节点公布的摘要**,只有本节点自己的 `auth.json` 会被打开。
- **主判据 = 跨 workspace 那一格**:对着修复前的模块跑,该测试失败且**输出为零**(症状是沉默);修复后两台互相点名,换回修好的模块即转绿。同 workspace 的仍能检出;凭据不同一行不打;记录指向的目录消失 ⇒ 不报且删项;目录还在但记录旧 ⇒ 仍报。parity 门追加一个字节即红。
- `bun test src/` 1280 pass / 0 fail;`tsc --noEmit` rc=0;doc-symbol-pins 两种 CI 参数形式与 doc-source-pins 全 rc=0;`docs/architecture.md` 两处行号 pin 漂移 +5,用该门自己的 `--fix` 重钉。
- **未做**:#1918 的 ③(token broker / 单刷新者)仍不在本版,单独排期。
