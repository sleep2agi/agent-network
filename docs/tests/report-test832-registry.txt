Observation mechanism
The previous report proved /api/mcp connected insufficient (2 of 3 cold runs
failed). This experiment loads an isolated V2 promise plugin from the test
directory. Its read-only RPC uses ctx.tool.list() AFTER registry transforms.
It returns ONLY {ready:boolean}, checking commhub_send_task and commhub_get_task.
It never executes a tool, reads a credential, changes a permission or warms the
model. The harness polls this observation with the remaining deadline after
the MCP connection check, then invokes the FIRST model turn directly.
Plugin and RPC polling currently exist ONLY in the Docker harness, not the
production runtime. No claim of shipping a readiness gate.
