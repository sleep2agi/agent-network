# agent-node — V1 admission 归属与会话缺失判定，v2.5.0-preview.153

这一版在 V1 共存运行时的 admission（提交前等待）路径中增加 task id / 提交者标记，以及会话查询返回 404 时的终止判定。默认 30 分钟预算不变。此前版本已有等待时长上报，本版不是首次加入忙碌可见性。

## 归属：等的是谁的那条任务

排队项在开始等的那一刻就绑定了 task id 与提交者，节点状态文本变成：

> 共享会话忙，任务还没提交，已等 3 分 20 秒（等 TUI 这轮结束；任务 5844f347 由 通信龙 提交）

看板上不止看得出「节点在等」，还看得出等谁。

## 终止：提交前会话查询返回 404

当状态表没有该 session 的条目时，运行时查询 `GET /session/:id`。404 观测计数至少 3 次、从首次缺失计时至少 2 秒后，以 `owner_left` 结束该次 admission；不会提交这条任务。发布包中的提示为：

> opencode 任务未提交：共享会话的负责人（TUI）已经离开，会话也不在了 —— 排队中的任务 5844f347（由 通信龙 提交）已被明确终止（owner_left），不是节点卡死。这一轮没有发出，可稍后重发。

**这不是 TUI owner 存活检测。** `owner_left` 是当前错误标记和提示措辞，404 只提供会话查询失败的证据，不能证明谁离开了。关闭 TUI 后会话仍可能存在；会话存在也不能证明 TUI 仍在线。提示中的“负责人已经离开”超出了实际观测范围，不能当作诊断结论。

**已知计数边界**：本版会在 session 查询的非 404 错误后重置计数，但外层 status 读取失败、命名 busy 状态等路径尚未全部重置。不能宣称任意瞬时错误都会重置，也不能将该门描述成已通过“连续缺失”的完整负控验收。修复和对应负控沿 CommHub #2011（父 #1879）及 [PR #2886](https://github.com/sleep2agi/agent-network/pull/2886) 跟踪；后续源码修复不改变已发布 `.153` 的字节或行为。

**不变**：30 分钟硬预算不变，也没有改成排队池；等待期间的可见状态不变。

## 支持与验收边界

- 本片接入 `opencode-copresence/runtime.ts` 的 V1 admission 路径；不据此声明 OpenCode V2 已有等价接线和验收。
- 不覆盖已提交 turn 的回复超时、归属错配或重启中断恢复（CommHub #1566）。
- 不自动重放任务，不清除 unknown write，也不接管或重启现役节点。
- npm 包发布不等于现有舰队已升级；每个节点的实际版本和行为须分别核验。

## Install

```bash
npm install -g @sleep2agi/agent-node@2.5.0-preview.153
```

用你要替换的那个节点同一份 Hub 与网络令牌，不要复制别的节点的 `config.json`。

## Upgrade

```bash
anet upgrade
```

或者把上面的版本装进这个节点自己的前缀，等它空闲时再重启这个节点。重启会丢掉该节点上正在进行的一轮对话。这一版不会替你重启任何节点。

停留在 2.5.0-preview.152 的节点不会自动获得本版新增的 task / 提交者标记和 404 判定；已有忙碌等待与超时行为保留。
