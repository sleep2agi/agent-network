# PR #3389 CI triage — 2026-11-08

Scope: make pull request #3389 (branch `release/ocv2-4150-backend`, head
b5de733f) green without changing product behaviour, without loosening a gate,
without touching main's pre-existing reds, and without version bumps.

Evidence base: this checkout at b5de733f, the public check-run list of that
commit (100 failing check-runs, 59 of them new relative to main 84afe24), and

## 1. e2e / test611 — `bin/cli.ts(8847,26)` TS2345

Before (reproduced locally, `agent-network` `tsc --noEmit`):

    bin/cli.ts(8847,26): error TS2345: Argument of type 'string | undefined' is not assignable to parameter of type 'string'.

Cause: `readOpencodePrivateProfileFile()` returns `string | undefined`
(`agent-network/src/opencode-preset.ts:388`, undefined when the file is absent),
and the source-delivery branch added in 7c12d59c passed it straight to
`JSON.parse`. Introduced by this PR.

Fix: `agent-network/bin/cli.ts` — read once, refuse when absent (same shape as
the existing guard at cli.ts:3208), then parse. No `!`, no cast: the route is a
private source-delivery launcher, so a missing profile is a refusal, not a
default.

After: `tsc --noEmit` exits 0 (`smol-toml` supplied from a local node_modules).

## 2. Docker build contexts — `Could not resolve: "../../contracts/..."`

Before (reproduced: agent-node copied to a directory with no sibling
`contracts/`, then `bun build src/cli.ts`):

    error: Could not resolve: "../../contracts/session-source-transport"
        at /app/agent-node/src/cli.ts:21:40
    (same for session-source-delivery, session-source-directory, session-project-create)

Cause: this PR adds six root-level `contracts/*.ts` files and imports them from
`agent-node/src/cli.ts` (module-scope capability constants),
`agent-node/src/runtime/session-source-*.ts`, and `server/src/server.ts` (via
`session-source-transport`). Docker images copy `server/` and `agent-node/`
individually, so `../../contracts` resolved outside the build context. Every
image that compiles agent-node or boots the hub from source failed at once —
that is the whole "hub semantics + guards", e2e, rename-ghost, rest-task-api,
v1-borrowed, shared-candidate, grok, node-secrets and daemon-suite cascade.

Fix: add `COPY contracts <parent-of-package-dir>/contracts` to the Dockerfiles
that copy `server` or `agent-node` source (297 files, one line each, placed just
before the first package copy so the destination matches
`COPY <pkg> <parent>/<pkg>`). Destinations were computed from each file's
`WORKDIR` and `COPY` destination, then independently re-verified: for every
stage, each package parent directory has a corresponding contracts copy.
`contracts/side-thread/v1`-only copies were widened to the whole directory
instead of adding a second copy.

Two Dockerfiles were deliberately left alone:

- `tests/hub-release-compat/Dockerfile` — built from a temporary context that
  mirrors only `server/` + `compat/`; it is release-prep only (NOT-IN-CI).
- `tests/test698-atomic-peer-reply/Dockerfile.legacy-hub` — built from a
  `git archive` of an older base commit that has no `contracts/`; adding the
  copy would break it.

After (reproduced: agent-node in the image layout with the sibling contracts):

    bun build src/cli.ts  →  1.85 MB cli.js, exit 0

and for the hub, `bun build src/session-source-transport.ts` no longer reports
`Could not resolve: ../../contracts/...` (it stops at third-party deps that the
Dockerfile's `bun install` provides).

## 3. agent-node typecheck ratchet

Before: two new error identities versus `agent-node/typecheck-baseline.txt`.

- `agent-node/src/runtime/session-source-directory.ts(216,52)` TS2345 — `page`
  is an untyped HTTP payload, so the repeated `page.cursor.next` read is not
  narrowed by the `typeof` guard and reached `Set<string>.add` as
  `string | undefined`. Fixed by binding the value once into `next` before the
  guard (also removes a double property read). Behaviour unchanged.
- `agent-node/src/runtime/side-thread/domain.ts` TS2367 — the message text
  embeds an unordered union, and the baseline carried the pre-PR member order;
  replaced the one identity string like-for-like (still one count).

After (local tsc 5.9.3 + @types/node 20.19.39, node-pty not installed here):
82 errors, added = only `Cannot find module 'node-pty'` — a local artifact;
`node-pty` is an `optionalDependencies` entry that the CI install provides.
Removed = one baseline identity that no longer reproduces (notice only).
