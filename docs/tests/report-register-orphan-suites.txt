# 三个孤儿门:改放独立 job,不塞 L1
source_commit=034f00647d42d38d5086d7fc057eb7824a441791

## 为什么不放 L1(证据)
CI 上 L0+L1 job 的真实耗时(main 近四次):141s / 135s / 118s(失败那次) / 148s,预算 300s。
qa.sh 的 build 是串行的(只有 docker run 并行),三个套件要各加一次 build,
其中 test679 带 javascript-obfuscator;单跑 run 已是 39s / 15s / 36s。
L1 自称「~16s parallel」,是快层 —— 这三个不该进去。

## 独立 job 的验证(按 job 里逐字相同的命令:只传 --build-arg,run 不带 -e)
  test224  --build-arg SOURCE_COMMIT          rc=0  Summary: PASS
  test597  --build-arg SOURCE_COMMIT          rc=0  RESULT: PASS
  test679  --build-arg TEST679_SOURCE_COMMIT  rc=0  RESULT: PASS

## build_args 推导仍保留在 qa.sh(独立成立)
原硬编码 if/elif 链的失效是静默的:套件加进 L1_TESTS 却忘了加分支,
它会在没有 SHA 绑定的情况下跑。等价性核过(test686/765/766/746 四个逐字相同)。
第一版漏了 || true,被 pipefail 打死在第一个套件,witnessed-red:
  去掉 || true → rc=1,日志停在 '· build qa-cli-01-hub-start',与 CI 症状逐字一致
  加回      → 三种 Dockerfile 形状各取一个跑真 qa.sh --l1,ALL PASS in 84s
