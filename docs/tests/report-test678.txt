Scope and compatibility
- B1(b): api_tokens.node_identity_epoch is persistent, not a timestamp cutoff.
  Pre-upgrade rows retain 0; all nine production mint statements explicitly
  write 1 (general credentials) or 2 (ownership-checked node credentials).
  A recursive source guard covers server/src, agent-node/src and both
  agent-network/src and agent-network/bin, including admin-reset's explicit 1.
- Bound credentials resolve by node_id AND network. Unbound credentials need
  exactly one alias match, never LIMIT 1. Authority is matching owner or exact
  binding; ownerless legacy rows additionally accept epoch-0 credentials.
- Both node-token issuance shapes check alias conflicts. Existing ownerless
  nodes need the same holder's live legacy/exact-bound credential to refresh.
  Refresh binds the token; it NEVER fills the node's NULL owner.
- New name-only node credentials bind once at successful registration.
  General credentials renamed during heartbeat are not promoted to epoch 2.
- PG serializes alias/ID issuance and registration with transaction-scoped locks.
  SQLite uses the existing synchronous transaction path.
- No implicit administrator claim, capability widening, version bump, daemon
  runtime or app change. Existing atok credentials are not mass-revoked.
- Six daemon/lifecycle fixture files exactly match base. The two task-event
  fixtures use mint -> real HTTP report_status; they assert NULL owner and exact
  token binding. No fixture patches an owner just to satisfy the new guard.
- PR fixture rationale, individually:
  * server/src/requirement-events-http.test.ts tests requirement event recording
    and visibility, not identity issuance. Its direct ownerless INSERT preceded
    token mint only as a shortcut. It now mints first, calls real HTTP report_status,
    and verifies NULL owner plus exact token binding; event assertions stay intact.
  * server/src/requirements-last-event-http.test.ts tests last_event projection,
    actor visibility and caching. The same shortcut is replaced by its existing
    MCP helper calling report_status after mint. NULL owner and exact binding are
    asserted; projection, filtering and caching assertions stay intact.
- Intentional behavior change for the PR: an ownerless legacy node without any
  historical node credential cannot be claimed by an administrator who merely
  knows its alias. No implicit admin exception is added. An explicit, audited
  claim flow is tracked in pool card #682 (parent #678, infrastructure project)
  and is not implemented here.
- Explicit-ID unknown-owner refusal retains node_owner_unclaimed. test688's
  source mutation was repointed to this guard, without weakening its assertion.
