test4-base V2 analysis

Scope
- Check whether the `network creation failed` and `alpha task leaked` regressions were caused by `utok_` hitting MCP 403.
- Identify the actual root cause in `tests/test4-base/run.sh`.

Findings

1. MCP in `test4-base` does not use `utok_`
- `AUTH_TOKEN` is assigned at line 5:
  - `AUTH_TOKEN="${COMMHUB_AUTH_TOKEN:-test-auth-token}"`
- All helper calls use that same variable:
  - `api_curl()` at line 7
  - `mcp_curl()` at line 8
  - `mcp_call()` at lines 214-227
- The server is started with the same token at line 22:
  - `COMMHUB_AUTH_TOKEN="${AUTH_TOKEN}" bun run src/index.ts`

Conclusion:
- `test4-base` MCP calls use the global CommHub bearer token, not a `register/login`-issued `utok_`.
- So the `utok_`-specific MCP 403 rule is not the reason for these two regressions.

2. `network creation failed` is caused by free-user network quota, not MCP auth
- In section 27, the script registers a new user `net-test-user` and stores its token in `NET_TOKEN`.
- That user is a normal free user, not admin.
- On registration, auth auto-creates a `default` network for the user.
- In `server/src/auth.ts`, free users have:
  - `max_networks_owned = 2`
- That means the user can own:
  - `default`
  - plus only one extra network
- But the script tried to create two additional networks:
  - `net-alpha`
  - `net-beta`

So the second creation can legitimately fail with quota exceeded.

3. `alpha task leaked` is a follow-on false failure after missing `NET_B_ID`
- After the second network creation fails, `NET_B_ID` is empty.
- The script still continues and runs:
  - `send_task(..., network_id="$NET_B_ID")`
  - `GET /api/tasks?network_id=$NET_B_ID`
- With empty `network_id`, the REST query is no longer meaningfully scoped to beta.
- That can cause the isolation assertion to see unrelated tasks and report:
  - `alpha task leaked to beta`

So this is not evidence of `utok_` MCP denial either.

Root cause summary
- Not caused by `utok_` MCP 403.
- Caused by section 27 using a newly registered free user that already owns `default`, then attempting to create two more owned networks.
- The later leak assertion is invalid once `NET_B_ID` is empty.

Fix applied
- Section 27 now reuses the admin token from section 26 (`$TOKEN`) to create `net-alpha` and `net-beta`.
- Added a guard so isolation checks only run when both `NET_A_ID` and `NET_B_ID` are present.
- If creation fails, the script now prints the API responses to expose the real server error instead of cascading into misleading leak failures.

Net result
- `AUTH_TOKEN` in `test4-base` is the global token and should pass MCP.
- The regression was in the test setup and quota assumption, not in the `utok_` MCP 403 behavior.
