# RFC-044：本地开箱即用 + 接入团队 Hub

- 状态：草案（admin 2026-11-16 口头同意方向）
- 负责人：ANet负责人
- 涉及：agent-network-app（桌面端）、agent-network（anet CLI / daemon / agent-node / Hub）

## 0. 背景

admin 2026-11-16：「什么时候能做到开箱即用」「现在下载下来大家都玩不了，上手成本有点高，看看怎么可以本地的先玩起来」「本地版本的节点如果也想接入到 Hub 如何做」。

## 2. 架构决策

### 2.1 双 Hub，不让 Daemon 承担 Hub 的功能

- **Hub 管状态和路由**（在线、任务、消息、组织、权限、文件），每个网络只有一份真数据。
- **Daemon 管执行**（在这台电脑上启动、停止和看护 Agent），可以同时给多个 Hub 干活。
- 本地 Hub 和云端 Hub 是**同一套代码**，App 连两边用的是同一套接口，没有第二套实现。
- 不做 Hub 之间的数据同步（联邦）：账号、权限、去重、离线冲突的成本太高。
- 对用户只显示一个「本地工作区：运行中」。以后可以把本地 Hub 和 Daemon 打包成一个进程，那只是打包方式，不改架构。

### 2.2 同一个 App，不另开软件

首屏两个入口：「在这台电脑上试试」（本地，不用注册）/「登录团队」（云端）。以后如果需要面向普通人的「个人版」，用同一套代码出一个不同品牌的安装包。

### 2.3 一个节点只属于一个 Hub（admin 2026-11-16 讨论后定）

不做「一个节点同时接多个 Hub」。一个节点只有一份对话记忆、工作目录和规则文件，同时接两边会出问题：
- 隐私串到团队：本地看过的私人文件、聊过的内容，可能在团队任务里被带出来；
- 规则打架：团队规则和本地规则冲突时，不知道听哪个；
- 权限边界说不清；
- 出了问题难查。

「接入团队」改成两个选项，都还是跑在用户自己的电脑上、用用户自己的 Key：
- **搬到团队**：节点整个换到团队 Hub；
- **复制一个到团队**：在团队 Hub 新建一个兄弟节点，模型、规则和技能相同，但记忆和任务各自独立。

## 3. 第一阶段：开箱即用

### 3.1 内置运行时（不联网下载 Node）
- 安装包里带 agent-node 和 anet 的运行时，二选一：
  - a) 带一份 Bun 运行时 + 预装好的包（约 +60–100MB）；
  - b) 用 `bun build --compile` 编成单文件（和 commhub sidecar 一样）。
- 优先试 b)；如果 claude-agent-sdk 之类需要单独 spawn 子脚本的依赖编译不了，就退回 a)。
- Windows 同时补齐：daemon 的 shell 调用改成不依赖 /bin/sh。

### 3.2 自动启动
- 点「启动本地工作区」后：启动 Hub → 启动内置 daemon → 确认 host_supervisor 在线，全程一个进度条，不用再点「一键安装」。
- 失败时说清楚卡在哪一步，并给「重试」和「查看日志」。

### 3.3 首次配模型 → 第一个 Agent
- 向导：选服务商（Anthropic / OpenAI / 国内兼容接口）→ 粘贴 API Key → 测试连通 → 自动创建第一个 Agent（使用内置运行时，不需要 CLI）→ 直接打开它的对话。
- Key 只存在本机（系统钥匙串，或者节点的 per-node secret），不上传。
- 待 admin 决定：是否提供「试用额度」（我们托管一个限额的 Key）。默认先做「用户填自己的 Key」。

### 3.4 验收
- 一台干净的 macOS 和一台干净的 Windows（都没装 Node 和任何 CLI）：从下载到第一句回复 ≤ 3 分钟，全程不出现命令行。

## 4. 第二阶段：接入团队

### 4.1 搬到团队（节点不用改）
流程：
1. 本地 Agent 页 → 「接入团队」；
2. 登录或注册云端 → 选网络和部门；
3. 确认页写清楚：任务在你的电脑上执行 / 用你的模型 Key / 默认只有你能找它；
4. daemon 把这个 Agent 从本地 Hub 停掉，用团队账号在云端 Hub 注册后重新启动。工作目录、规则、技能都不变。

显示：
- 本地列表：「已接入 · 团队名」；
- 团队组织图：「运行在 XX 的电脑上」，关机就离线。

退出：点「退出团队」就搬回本地，团队那边立即离线。

默认安全设置：模型 Key 和本地文件永远不上传；接入后权限默认「只有主人能找它 / 只读 / 不能管别人」。

实现：daemon 同时连本地和云端两个 Hub（每个 Hub 一份连接配置）。「搬家」就是把节点从一份配置挪到另一份。

### 4.2 复制一个到团队
- 在团队 Hub 新建一个节点，复制源节点的运行时、模型、规则文件和技能，不复制对话记忆、会话和任务历史；
- 工作目录默认新建一个（避免两个节点抢同一个目录），用户可以手动选择共用；
- 两个节点在 App 里显示为「兄弟」，可以互相跳转。

### 4.3 三期：统一列表
- App 侧栏同时显示多个 Hub 的 Agent，用「本地 / 团队名」标签区分，不用切换工作区。

## 5. 顺序与里程碑（按「最便宜先出效果」排）

| 步骤 | 内容 | 粗估 |
|---|---|---|
| ① Mac 最小可用 | 启动本地工作区后自动接着装 daemon + 首次填模型 Key，用不需要 CLI 的运行时自动建第一个 Agent，然后打开对话 | 2–3 天 |
| ② Windows | daemon 支持 Windows（去掉 /bin/sh，私有 Node 支持 win-x64） | 1–2 周 |

先做 ①，看效果再定 ②～⑤。
